# CLEAN-01 파일 정리 기록

## 판정 기준

삭제는 대체 위치, repository 전체 참조 0, 복구 방법을 모두 확인한 파일에만 수행했다. `supabase/migrations`와 `docs/REFACTORING_PLAN.md`는 수정·삭제·rename하지 않았다.

## 삭제 목록

| 삭제 경로 | 삭제 이유 | 대체 위치 | 참조 0 증거 | 복구 방법 |
|---|---|---|---|---|
| `src/lib/activityLog.ts` | React setter와 Supabase insert를 한 파일에서 선택하던 구형 facade. 단일 RepositorySet 및 lib DB write 0 계약과 충돌 | `src/data/activityLog.ts`, `src/data/local/localActivityLogWriter.ts`, `src/data/remote/supabaseActivityLogWriter.ts` | `rg -n "lib/activityLog|recordActivityLog" src --glob "!src/lib/activityLog.ts"` 결과 모든 호출이 `src/data/activityLog.ts` 또는 그 repository 소비자로 해석됨 | `git show e6ce717:src/lib/activityLog.ts`로 원본 확인. 복원보다 현행 writer에 필요한 기능을 추가하는 방식을 사용 |

## 보존 목록

- `docs/REFACTORING_PLAN.md`: 계획에서 명시적으로 보존하며 현재 문서가 참조한다.
- `src/data/mutations/master.ts`: Product/Duty/Invite 독립 facade로의 기존 공개 import 호환 re-export다.
- 기존 `supabase/migrations/*`: 배포 이력이며 append-only다.
- 기존 운영·배포 문서: README와 다른 runbook의 참조가 남아 있으므로 삭제하지 않았다.

## 자동 재발 방지

`npm run lint`의 dependency checker는 `src/lib` 안의 Supabase write 형태(`insert`, `update`, `delete`, `upsert`, `rpc`)를 거부한다. negative fixture가 깊은 경로에서도 이 위반을 검출하는지 확인한다.
